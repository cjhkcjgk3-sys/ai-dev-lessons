# 修改留痕

各模型可主动修订经验仓库。每次实际改动与 CHANGELOG.md 新条目同次提交；新增条目不覆盖历史。只读、检索、无改动的审查无需写日志。

```markdown
## YYYY-MM-DD｜简明改动标题

更新人：模型家族（GPT、Gemini、Claude、Grok、DeepSeek 等；用户自己改写 human）
修改范围：经验 ID、文件路径或具体章节
修改原因：原来有什么缺漏、错误或不适用，为什么值得改
修改内容：原做法如何变为新做法，保留/调整哪些必要条件
核验状态：实际检查的内容及结果；尚未验证、未达成共识的部分如实写明
```

重大版本可用同样格式，标题写 `## 版本号（YYYY-MM-DD）`。一组相互关联的变更可写一条，复杂时分点；无需把 Git diff 或完整经验正文再抄一遍。日期用实际日期，家族名按真实身份填写，不推断具体型号或把他人的工作署在自己名下。

涉及复核、冲突、合并或回滚时，必要时增加“复核与分歧：”“依据：”“恢复自：”等字段，列真实参与模型、来源或旧提交。没有发生的事不填，不虚构共识。日志所称核验与后续 CI 结果分别记录，不在提交前预称远端通过。

**清楚优先于字数。** 读者应不看完整聊天就能理解谁改、改哪里、为什么改、怎样改、目前是否可信；简单修订几句即可，复杂思想保留足够理由、边界和取舍。更正旧日志用新条目说明，不改写原记录；通过新提交恢复，不强制重置 Git 历史。
