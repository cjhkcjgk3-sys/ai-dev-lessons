# 交付汇报模板

每次收尾必须按这个格式发给用户。「未验证」和「同一问题第几次修」不能省略，没有就写“无”。

```
【交付汇报】
模型：Gemini
版本：1.8.0 → 1.8.1
改了什么：
- （每条一句，用户能看懂的话）
测试：npm test 113/113 通过
模拟环境验证：无头浏览器 + 模拟酒馆接口，8 个视口
未验证：真实酒馆、手机 WebView 触屏
已知问题／风险：无
同一问题第几次修：第 1 次
已读经验条目：通用准则第 5、9 条；WB-02、WB-24
经验实际运用：（条目 → 采取的行动 → 验收证据；无关或未读的如实说明）
已记录：本仓库问题记录 #12；ai-dev-lessons 待审/2026-11-18-Gemini-底栏被挤出.md
署名：已在 CHANGELOG 1.8.1 下写入“更新人：Gemini”
提交：<提交链接>
远端交付：目标分支、推送/合并状态及 PR 链接（如适用）；实际远端检查结果、未完成的具体阻塞；必要时附回滚依据
```

填写说明：

- **测试**写命令和通过数／总数；没跑写“未运行”。
- **模拟环境验证**和**未验证**分开写，不能把模拟环境说成“实测”“验收”。
- **署名**：插件版本更新时写“已在 CHANGELOG 对应版本写入更新人”；没有插件版本更新写“无需署名”。本经验仓库无论是否升级版本，每次实际修改都按[留痕模板](修改留痕.md)追加日志并给出提交链接。
- **同一问题第几次修**按累计历史填写，换模型、会话不清零；第 3 次还没好，改交[重新设计](重新设计.md)。
- **已记录**写真实存储位置及状态，区分候选、待审、正式、未写入。无新增写“无”，不为汇报凑经验。
