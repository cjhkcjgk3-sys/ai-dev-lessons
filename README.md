# AI 写代码踩坑经验库

这里记录 AI（GPT、Codex、Gemini 等）帮我写插件时**真实踩过的坑**：出了什么问题、为什么会出、怎么解决、以后怎么预防。每一条都附证据（提交链接、文件位置或我的原话），不写猜测。

## 给 AI 的使用说明

1. **动手前先读**：先读 [通用准则](通用准则.md) 和 [检查清单](检查清单.md)，再读与你要改的插件对应的案例文件。
2. **改完再对照**：提交前逐条过一遍 [检查清单](检查清单.md)。做不到的项目要在汇报里写明“没做”，不能写成“已验证”。
3. **踩坑就记录**：修完一个问题，按 [模板](模板.md) 追加到对应案例文件；同类问题出现两次以上，把规律提炼进 [通用准则](通用准则.md)。
4. **只写有证据的内容**：每条至少一个提交链接、文件行号或用户原话。没解决的标「未解决」，不确定的标「待确认」。

## 使用环境（写代码时要考虑）

- SillyTavern 1.19，插件经 GitHub 仓库链接安装。
- 手机端是 SillyDroid（Android WebView，触屏）；电脑端是浏览器。两端都要能用。
- 我习惯让 AI 直接推送到 main；大改动、删功能、改布局前先问我。
