# AI 人机协作经验知识库（ai-dev-lessons）

V2.1：可持续积累、多模型共同修订的人机协作经验库。保存有实际指导价值的思想、方法、设计原则、用户反馈、实践经验和避错经验，让不同模型及 Agent 在新任务中主动继承，不必让用户反复提醒。原 16 条已审核开发方法、11 组准则、项目案例及审核历史继续有效（在原适用范围内）。

## 给 AI 的入口

1. 阅读 [仓库规范](正式/仓库规范.md) 与 [总索引](总索引.md)，识别本次任务领域、专项、项目、阶段和风险，读取适用正式经验正文。软件开发还要读 [工作流程](正式/工作流程.md)、[通用准则](正式/通用准则.md) 与相关 [检查清单](正式/检查清单.md)。不再默认读完整个正式区。
2. 将命中的经验用于具体行动和验收。开发开工报告写相关条目编号及采取的措施；大改先确认，同一问题第三次仍未解决就停下重新设计。保留旧开发流程的权限、测试、署名与收尾要求。
3. 主动发现有用经验，但不逐轮总结。结合用户原意、模型解释与后续反馈提炼完整思想；查重、定范围、标明确认与证据状态。共享经验经授权公开后提交 [待审](待审/README.md)，项目专属写回项目仓库。具体工具知识进入 [技术参考](技术参考/README.md)。
4. **各模型均可主动修改本仓库（含正式区），每次修改须在 [CHANGELOG](CHANGELOG.md) 留痕。** 有具体改进依据即可修订，不必每次请示；保留用户明确要求、原有有效信息及真实确认状态。新思想的成熟度与复核按[协作维护](正式/仓库规范.md#多模型协作与修改权限)处理，待审只作参考。当前仓库公开，写入权限不等于允许公开私人内容。

## 原有开发环境约定

适用于相关酒馆插件：SillyTavern 1.19，插件经 GitHub 链接安装；手机 SillyDroid（Android WebView，触屏）和电脑浏览器均为正式环境，以项目实际支持版本为准。通常直接推送 main，不强推；大改、删功能、改布局或数据格式先确认。正式版本更新仍在各插件 CHANGELOG 写“更新人：模型家族名”，本库经验不冒充具体模型的未经确认历史。

## 审核与自动检查

[待审机制](待审/README.md)保留候选复核和历史；已有正式经验可以由任一具备写入权限的模型直接改进。每次实质修改同步追加日志，写明日期、模型家族、涉及内容、为什么改、怎样改、核验状态；历史日志只追加不覆盖。意见有争议时保留分歧和适用条件，不以最后一次写入取代论证；真实独立的跨模型共识可作为采纳依据，不冒充用户批准或验证结果。[自动检查](.github/workflows/check.yml)核对提交是否新增符合格式的日志并保留历史，不判断观点正确或模型身份。未开启强制分支保护时只能在提交后标红；[CODEOWNERS](.github/CODEOWNERS)保留所有者审阅入口。
