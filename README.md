# AI 人机协作经验知识库（ai-dev-lessons）

V2.3：可持续积累、多模型共同修订且具有明确规则优先级的人机协作经验库。保存有实际指导价值的思想、方法、设计原则、用户反馈、实践经验和避错经验，让不同模型及 Agent 在新任务中主动继承，不必让用户反复提醒。原 16 条已审核开发方法、11 组准则、项目案例及审核历史继续有效（在原适用范围内）。

## 给 AI 的入口

1. 阅读 [仓库规范](正式/仓库规范.md)（尤其[规则优先级](正式/仓库规范.md#规则优先级与冲突裁决)）与 [总索引](总索引.md)，识别本次任务领域、专项、项目、阶段和风险，读取适用正式经验正文。软件开发还要读 [工作流程](正式/工作流程.md)、[通用准则](正式/通用准则.md) 与相关 [检查清单](正式/检查清单.md)。不再默认读完整个正式区。按[验证互认与继承](正式/仓库规范.md#跨模型验证互认与继承)复用已有适用的验证成果，新会话不要求重新验证。
2. 将命中的经验用于具体行动和验收。按[主动交付与持续授权](正式/仓库规范.md#主动交付与持续授权)完成必要检查、提交、推送及合并，普通可恢复操作无需再次确认。开发开工报告写相关条目编号及采取的措施；大改先确认，同一问题第三次仍未解决就停下重新设计。保留旧开发流程的权限、测试、署名与收尾要求。
3. 主动发现有用经验，但不逐轮总结。结合用户原意、模型解释与后续反馈提炼完整思想；查重、定范围、标明确认与证据状态。共享新经验经授权公开后按 [待审](待审/README.md) 复核，有依据的已有经验改进可直接修订，项目专属写回项目仓库。具体工具知识进入 [技术参考](技术参考/README.md)。
4. **各模型均可主动修改本仓库（含正式区），每次修改须在 [CHANGELOG](CHANGELOG.md) 留痕。** 有具体改进依据即可修订，不必每次请示；保留用户明确要求、原有有效信息及真实确认状态。新思想的成熟度与复核按[协作维护](正式/仓库规范.md#多模型协作与修改权限)处理，待审只作参考。当前仓库公开，写入权限不等于允许公开私人内容。

## 原有开发环境约定

适用于相关酒馆插件：SillyTavern 1.19，插件经 GitHub 链接安装；默认以手机 SillyDroid（Android WebView，触屏）为唯一 UI 适配及验收目标，界面沿用酒馆原生 UI 逻辑；电脑端等其他 UI 适配仅在实际需求明确后纳入，由项目自身文档明确对应布局、交互及验收基线；项目既有明确支持约定仍有效。具体默认规则见[通用准则第 2、8 组](正式/通用准则.md)，以项目实际支持版本为准。默认设备性能基准及特殊需求处理见[方法 15](正式/领域经验/软件工程/方法-15.md#method-15)，多工作区容量设计见[方法 11](正式/领域经验/软件工程/方法-11.md#method-11)。通常直接推送 main，不强推；大改、删功能、改布局或数据格式先确认。正式版本更新仍在各插件 CHANGELOG 写“更新人：模型家族名”，本库经验不冒充具体模型的未经确认历史。

## 审核与自动检查

[待审机制](待审/README.md)保留候选复核和历史；已有正式经验可以由任一具备写入权限的模型直接改进。每次实质修改同步追加日志，写明日期、模型家族、涉及内容、为什么改、怎样改、核验状态；历史日志只追加不覆盖。意见有争议时保留分歧和适用条件，不以最后一次写入取代论证；真实独立的跨模型共识可作为采纳依据，不冒充用户批准或验证结果。[自动检查](.github/workflows/check.yml)核对提交是否新增符合格式的日志并保留历史，不判断观点正确或模型身份；同时轻量检查仓库 Markdown 正文、模板和索引中支持的本地链接、标题/显式锚点及经验编号，历史引用问题单独警告，具体范围见[经验质量维护](正式/经验质量维护.md)。未开启强制分支保护时只能在提交后标红；[CODEOWNERS](.github/CODEOWNERS)保留所有者审阅入口。
