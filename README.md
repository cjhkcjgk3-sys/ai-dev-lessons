# AI 人机协作经验知识库（ai-dev-lessons）

V2.0：从 AI 写代码踩坑经验库扩展为长期人机协作经验库。保存有实际指导价值的思想、方法、设计原则、用户反馈、实践经验和避错经验，让不同模型及 Agent 在新任务中主动继承，不必让用户反复提醒。原 16 条已审核开发方法、11 组准则、项目案例及审核历史继续有效（在原适用范围内）。

## 给 AI 的入口

1. 阅读 [仓库规范](正式/仓库规范.md) 与 [总索引](总索引.md)，识别本次任务领域、专项、项目、阶段和风险，读取适用正式经验正文。软件开发还要读 [工作流程](正式/工作流程.md)、[通用准则](正式/通用准则.md) 与相关 [检查清单](正式/检查清单.md)。不再默认读完整个正式区。
2. 将命中的经验用于具体行动和验收。开发开工报告写相关条目编号及采取的措施；大改先确认，同一问题第三次仍未解决就停下重新设计。保留旧开发流程的权限、测试、署名与收尾要求。
3. 主动发现有用经验，但不逐轮总结。结合用户原意、模型解释与后续反馈提炼完整思想；查重、定范围、标明确认与证据状态。共享经验经授权公开后提交 [待审](待审/README.md)，项目专属写回项目仓库。具体工具知识进入 [技术参考](技术参考/README.md)。
4. **未经用户审核授权，不得改 正式/。** 只有正式区是已审核共享规范与经验的权威；经验性质与适用范围决定使用方式。待审只作参考，不得自动晋升。当前仓库公开，写入权限不等于允许公开内容。

## 原有开发环境约定

适用于相关酒馆插件：SillyTavern 1.19，插件经 GitHub 链接安装；手机 SillyDroid（Android WebView，触屏）和电脑浏览器均为正式环境，以项目实际支持版本为准。通常直接推送 main，不强推；大改、删功能、改布局或数据格式先确认。正式版本更新仍在各插件 CHANGELOG 写“更新人：模型家族名”，本库经验不冒充具体模型的未经确认历史。

## 审核与自动检查

[待审机制](待审/README.md)保留一条一文件、合并/通过/驳回、一次性审核授权与积压提醒。[自动检查](.github/workflows/check.yml)核对正式区提交说明是否包含“审核通过”，不是用户授权的技术证明；未开启强制分支保护时只能标红，不能阻止直接推送。[CODEOWNERS](.github/CODEOWNERS)继续保留。私有或未授权内容不得因为工具可写而上传。
