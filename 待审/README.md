# 待审区

任何模型都可以往这里交新经验或修改意见。**这里的内容只供参考，不是规则**；只有 `正式/` 里的内容算规则。

## 本轮有效清单与范围

2026-11-18 按用户最新要求重整为 **10 条**（编号 01–10），均是待审核建议；原 18 条去向见[处置表](../整理记录/2026-11-18-待审重整处置表.md)。重整不是审核决定，`已驳回/` 没有新增内容。

关注能跨项目复用的设计与开发方法，每条说明现象/错误假设、原则、预防步骤、验收和证据边界。具体工具技巧放[技术参考](../技术参考/)，专属故障留来源仓库；不为每个例子单建一条经验。

编号仅作本轮目录，不改变一条一文件、由用户审核的机制。

## 怎么交

1. 一条一个文件，文件名 `YYYY-MM-DD-模型-简题.md`（如 `2026-11-18-Gemini-底栏被挤出.md`）。
2. 按[待审条目模板](../模板/待审条目.md)填写：提交模型、来源仓库、建议归类（通用或某模型专项）、建议新增或修改、证据。
3. **不要改 `正式/` 里的任何文件**，想改正式条目也在这里写修改意见。

## 怎么审

审核人是用户，或用户指定的模型代审；代审的结果最后要用户确认。

| 结果 | 怎么处理 |
| --- | --- |
| 通过 | 并入 `正式/` 对应文件，注明“审核人、日期”，删除这条待审 |
| 合并 | 并入已有的正式条目，删除这条待审 |
| 驳回 | 移到 `待审/已驳回/`，文件开头加一行驳回理由；留着防止别的模型重复提交 |

- 把内容并入 `正式/` 的那个提交，说明里必须写“审核通过”，否则自动检查会标红。只有用户或用户指定的审核人可以这样写。
- 待审积压超过 20 条，或最早一条放了超过两周，就提醒用户集中审一次。
- 交新条目前先看一眼 `已驳回/`，别重复提交被驳回过的内容。
