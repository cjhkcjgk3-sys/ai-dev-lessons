# 软件工程经验索引

适用：软件设计、实现、调试、验证、交付。先读[开发工作流程](../../工作流程.md)及[通用准则](../../通用准则.md)；根据当前阶段和风险选读完整方法，不得只报编号代替落实。相关验收用[检查清单](../../检查清单.md)。

本目录的 01–16 初始内容继承 2026-11-18 用户审核记录，后续模型修订与复核见[更新日志](../../../CHANGELOG.md)，不得将后续修改自动视为用户已审核。方法内以酒馆、世界书等为例时保留其原边界；非酒馆项目不可照搬宿主专用要求。[旧编号兼容入口](../../通用方法.md)。

| 正式方法 | 触发场景 | 用途 |
| --- | --- | --- |
| [01｜UI一致性是同一套操作语言](方法-01.md) | 界面、组件、交互 | 新增或修改界面时，沿用既有语义、控件和反馈；有意差异需有任务理由。 |
| [02｜先复用再扩展最后才新建](方法-02.md) | 设计、实现 | 动手前查项目、宿主和相关实现；按业务契约判断复用，避免重复或强行合并。 |
| [03｜先定目标边界和优先级再实现](方法-03.md) | 需求、方案 | 明确用户目标、功能边界、优先级及冲突关系，再决定实现。 |
| [04｜按用户流程组织界面而非堆按钮](方法-04.md) | 界面、交互 | 沿用户操作路径组织主次操作，保证关键操作和退出可达。 |
| [05｜用输入维度定义需求而非少数样例](方法-05.md) | 需求、匹配、测试 | 按输入维度、组合、边界与反例建立完整需求和测试。 |
| [06｜按风险和判断依据分层容错](方法-06.md) | 输入、匹配、写入 | 可逆低风险操作适当容错；不确定或高代价动作严格确认。 |
| [07｜反例要推翻错误假设而非扩常量](方法-07.md) | 排错、算法、复发 | 反例暴露假设时重新检查机制，不继续盲加阈值、常量或特例。 |
| [08｜改动先做影响分析再校准联动](方法-08.md) | 修改、状态、接口 | 列出共享状态、调用者、消费者和联动影响，校准并验证相关路径。 |
| [09｜用全流程和回归验证设计](方法-09.md) | 测试、验收 | 覆盖实际用户流程、正确与错误场景、边界以及关联回归。 |
| [10｜交付结论不能超过证据范围](方法-10.md) | 验证、汇报 | 分别报告自动测试、模拟和真实环境；结论对应实际证据。 |
| [11｜窗口布局先验证任务容量](方法-11.md) | 界面、窗口、触屏 | 按内容容量、视口、焦点、滚动与退出可达性验证窗口。 |
| [12｜异步任务必须有身份和完整收尾](方法-12.md) | 异步、取消、并发 | 任务身份隔离、取消重启、晚到响应、资源释放和收尾均需处理。 |
| [13｜保存成功必须对应完整且可核对的提交](方法-13.md) | 持久化、写入 | 区分完整、部分和未知结果，核对提交，处理重试与并发。 |
| [14｜升级导入恢复必须保留用户已有成果](方法-14.md) | 迁移、导入、恢复 | 验证后替换，保护原有用户成果、格式兼容和恢复路径。 |
| [15｜性能和恢复预算要贯穿整个处理链](方法-15.md) | 性能、重试、恢复 | 以端到端预算约束重试、拆分、并发及长期资源占用。 |
| [16｜外部内容与敏感数据要守住信任边界](方法-16.md) | 权限、外部输入、日志 | 外部内容按数据处理，限制权限、日志、导出及外发范围。 |

其他专项：[插件开发](../../专项经验/插件开发/索引.md)；具体工具和环境见[技术参考](../../../技术参考/README.md)。
