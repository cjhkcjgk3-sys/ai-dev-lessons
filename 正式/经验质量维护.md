# 经验质量维护

适用：仓库治理、复核。性质：按需采用的维护方法，不新增日常强制全库扫描。来源：GPT 的经验回放、结构检查待审建议及其他模型反向索引、失效复查建议；用户授权整合。未开展多模型效果实验。

## 失效与复查

在相关条件变化时复核：模型换代或实际行为变化、宿主或依赖升级、接口变化、设备基准更新、可靠反例或更有效的方法。依赖环境的条目标明适用版本、条件和需复查部分；普适思想不设统一有效期。旧模型案例不自动代表新一代仍会犯错。已替代或失效的条目退出默认有效入口，保留 ID、历史与替代关系。依[验证互认](仓库规范.md#跨模型验证互认与继承)只复核受影响内容。

实践状态“待实战核验”与正式/待审、逻辑复核及规则效力分别判断。已采纳且逻辑充分的指导经验可以正常使用；该标记只表示尚无足够实际应用效果证据，不是要求每次使用重新验证、另开实测任务或降为待审。相关实际任务自然产生证据时，按真实覆盖范围补记、调整或去除标记；出现执行成本过高、反例或复发时，检查原因后保留、精简、合并或修订。不规定固定应用轮数或统一到期日。

## 经验回放

仓库价值看实际行为、验收质量、返工和用户纠正负担，而非条目数量。重要变化或问题复发时，用少量匿名历史案例或合成任务回放：先定任务、环境、可观察成功标准；测试输入不直接泄露答案，记录实际行为与证据。必要时比较同模型使用不同经验版本、是否读取相关经验或不同模型的表现，控制任务与环境差异，不凭一次结果断言因果。

复发时区分检索遗漏、正文缺漏、理解错误、未执行、验收漏判或环境变化，据此修订索引、正文或项目验证。示例：给双栏界面增加工作区，处理数百条记录，观察是否重估整体视口、内容容量和主任务，避免推拉式挤压。该示例尚未实际回放。小修订无需例行回放，不建大型评测平台。

## 确定性结构检查

程序一次性读取仓库内 Markdown 文档，检查普通正文、模板和索引中支持的本地行内链接、引用定义、常规标题锚点及显式 ID；保留稳定编号与活动索引误收待审的检查。跳过代码示例、HTML 注释和外部链接；历史整理记录、案例、驳回记录及 CHANGELOG 的旧引用问题报告有限警告，不阻塞正常维护或改写历史。活动正文引用历史材料时仍严格检查目标。脚本仅覆盖当前仓库常用 Markdown 写法，不声称实现完整 GitHub Markdown 渲染器。语义冲突、质量及证据由模型判断。用已知正反例验证检查本身，不全网探测，不把 CI 通过当经验验证。具体覆盖以[工作流](../.github/workflows/check.yml)及脚本为准。
