# 检查清单

软件项目提交、推送、交付前按实际任务与支持范围核对。规则适用性和冲突见[仓库规范](仓库规范.md#规则优先级与冲突裁决)；不适用说明原因，适用但做不到的写“未做”，不能混淆或绕过必需发布验证。经验库文档维护用相应文档、链接及留痕检查，不套用插件发布清单。

## 开工前

- [ ] 读过[仓库规范](仓库规范.md)、[总索引](../总索引.md)、通用准则和工作流程；按[软件工程索引](领域经验/软件工程/索引.md)读本次适用方法正文及相关专项/案例，未读到的关键要求已说明。
- [ ] 开工汇报第一句写相关条目编号，并说明具体行动与验收；收尾核对实际落实，不只列编号。
- [ ] 查过能不能复用（本仓库代码、酒馆自带功能、兄弟插件），汇报里写明查了哪些。
- [ ] 未经授权的布局、功能删除、数据格式或交互变更，按[方案确认](../模板/方案确认.md)取得批准；已明确授权的同一范围无需再次确认。
- [ ] 已查同一问题的历史及累计次数；每次失败先核对根因和关联场景，发现原设计假设不成立立即停止无效修补并复核方案，不等用完三次；第 3 次仍未解决停止修改，发[重新设计](../模板/重新设计.md)，换模型/会话不清零。
- [ ] 要做匹配或判断类功能：先列好样例表（该配、不该配、留给人工），写成测试。

- [ ] 高风险设计已预演关键失败、验证决定成败的前提；复杂度有收益，阶段闭环不擅自缩减最终目标（[02](通用方法.md#method-02)、[03](通用方法.md#method-03)）。

## 写代码时

- [ ] 同一个判断只有一份实现，显示、勾选、预览、写入都调用它。
- [ ] 多个功能控制同一对象或资源时，明确权威、优先级、同级裁决、互斥/并行与交接恢复条件；实现中共用实际仲裁契约，测试同时触发、不同顺序及迟到结果（[08](通用方法.md#method-08)）。
- [ ] 对有实质风险的处理链按需要设置多层防护，写清各层拦截条件和失败处理；测试前层漏判时后层仍能保护关键约束，正常输入不被误杀，不机械堆层（[06](通用方法.md#method-06)）。
- [ ] 列出会让状态失效的操作（换书、重载、搜索、换边、删除、收起），每一种都处理了。
- [ ] 同一个选择器对应多个按钮时，全部绑定了事件（或用事件委托）。
- [ ] 删除/覆盖等高风险写入：范围预览与确认齐全，同一操作重试不重复新增；显示需求没有去改用户数据（[13](通用方法.md#method-13)）。
- [ ] 高频操作（勾选、点选）只做必要刷新，优化未破坏保存/恢复契约（[15](通用方法.md#method-15)）。
- [ ] 异步身份、取消重启、晚到响应与资源收尾检查过（[12](通用方法.md#method-12)）。
- [ ] 写入前后故障、部分/未知结果、重复提交与并发冲突有明确处理（[13](通用方法.md#method-13)）。
- [ ] 升级/导入先验证再替换；自定义成果、旧格式与恢复路径受保护（[14](通用方法.md#method-14)）。
- [ ] 重试/拆分/并发共用任务预算，连续使用不无界积累资源（[15](通用方法.md#method-15)）。
- [ ] 有扫描、递归、持续渲染或后台任务时，按实际风险设运行范围、深度、累计量、触发频率、时间、资源预算和停止条件；验证深/宽结构、循环引用、重复触发、多任务负载及退出清理等适用场景，超限结果可辨认且能安全恢复（[15](通用方法.md#method-15)）。
- [ ] 外部内容按数据处理；权限、日志、导出与外发不越过必要范围（[16](通用方法.md#method-16)）。

- [ ] 实质故障风险的执行链有必要、脱敏、有界诊断信息（[17](通用方法.md#method-17)）；Agent 运行时按[专项](专项经验/Agent开发/索引.md)核对适用工具、门控、预算及概率性验收。

## 界面

- [ ] 用的是酒馆原生类名和主题变量。
- [ ] 名词统一，和文档、确认框一致。
- [ ] 最常用的操作要几步？能不能少一步？出错提示说清了该怎么办？
- [ ] 320×568、390×844、横屏 740×360、桌面 1280×900 下：
  - [ ] 默认主操作与关键退出明显可达（检查默认可见性不要先 `scrollIntoView`）；
  - [ ] 无横向溢出，弹出面板不出屏；
  - [ ] 常规按钮简洁、横向可读，不逐字挤成竖长条；必要换行/长标签仍清楚可达（[04](通用方法.md#method-04)）。
- [ ] 窗口最小容量、嵌套层级、焦点、滚动、切换后的输入保留符合任务；新增工作区时核算整体可用空间，以真实长列表和必要的同时对照任务验证默认布局，不能靠反复拖动分隔条、叠窗或压缩必要区才勉强使用（[11](通用方法.md#method-11)）。
- [ ] 打开界面看一眼：插件名、标题、版本号都是对的。

## 测试

- [ ] 性能相关改动已明确目标设备档位、具体参考配置及代表任务；适用用户项目默认安卓较当代骁龙旗舰落后约三代、PC 普通中档。核对持续使用、资源峰值和响应；特殊硬件需求另提，模拟或未实机验证如实说明（[15](通用方法.md#method-15)）。
- [ ] 重要验收能识别目标已知错误和正常反例，不改弱断言或替用户修正状态（[09](通用方法.md#method-09)）。
- [ ] 跑了本次适用的自动测试；重大代码改动执行适用的完整套件（写明条数和结果）。必需发布验证未通过不得标为可用版本。
- [ ] 跑了浏览器检查（写明是模拟宿主）。
- [ ] 用上千条的大世界书或大名单试过。
- [ ] 真实酒馆里试过？真实手机（SillyDroid）上试过？没有就写“未实机验证”。

## 收尾

[快速自检](../模板/交付前快速自检.md)是入口，不代替适用检查；实际交接可用[任务交接摘要](../模板/任务交接摘要.md)。

- [ ] 若为插件用户可见版本更新，版本号已升（有 manifest.json、package.json 时一致）；经验库普通修订不要求升版本。
- [ ] 项目实际存在且受影响的 README、PLAN、NEXT、VERIFICATION 等文档已同步；搜过旧说法，不为无关任务强建文件。
- [ ] 没有提交过期的测试结果、临时文件或密钥。
- [ ] 清理了本次产生且确认可丢弃的临时残留；不清理用户已有成果、备份或未经授权的分支。
- [ ] 清单、索引、校验和与实际文件一致（数量、文件名对得上）。
- [ ] 没有半成品：做不完的写清做到哪、剩什么，交接说明写进 NEXT 或问题记录。
- [ ] 推送后到远端核对最终状态：最新提交、CI 结果、文件确实在。
- [ ] 提交信息写了改了什么、为什么。
- [ ] 有实质新增的经验已提炼：专属问题记项目，通用新经验获准公开后按待审流程；已有经验有依据的改进可直接修订并留痕；无新增不凑数。
- [ ] 这次是版本更新的话，已在 `CHANGELOG.md` 对应版本下写“更新人：家族名”。
- [ ] 按[交付汇报](../模板/交付汇报.md)发给用户，“未验证”和“同一问题第几次修”没有省略。
- [ ] 按[主动交付与持续授权](仓库规范.md#主动交付与持续授权)完成可恢复的提交、推送及必要的 PR 合并，核对目标分支和远端检查结果；不重复请示、不强推。真实阻塞说明原因，未完成不得假报。
