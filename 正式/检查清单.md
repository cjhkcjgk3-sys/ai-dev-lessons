# 检查清单

提交、推送、向用户汇报前逐项核对。做不到的项目，在汇报里写“未做”和原因。

## 开工前

- [ ] 读完整个 `正式/`：通用准则、检查清单、工作流程、全部模型专项、相关案例。
- [ ] 开工汇报第一句写了相关条目编号。
- [ ] 查过能不能复用（本仓库代码、酒馆自带功能、兄弟插件），汇报里写明查了哪些。
- [ ] 这次改动会不会换布局、删功能、改数据格式、改交互方式？会的话先发[方案确认](../模板/方案确认.md)，等用户回复“可以”。
- [ ] 这是同一问题第几次修？第 3 次还没好就停，发[重新设计](../模板/重新设计.md)。
- [ ] 要做匹配或判断类功能：先列好样例表（该配、不该配、留给人工），写成测试。

## 写代码时

- [ ] 同一个判断只有一份实现，显示、勾选、预览、写入都调用它。
- [ ] 同一件事有多种控制方式时，写清优先级，并在代码里体现。
- [ ] 列出会让状态失效的操作（换书、重载、搜索、换边、删除、收起），每一种都处理了。
- [ ] 同一个选择器对应多个按钮时，全部绑定了事件（或用事件委托）。
- [ ] 写入、删除、覆盖：有预览、有确认；重复执行不会多出数据；显示需求没有去改用户数据。
- [ ] 高频操作（勾选、点选）只做局部刷新。

## 界面

- [ ] 用的是酒馆原生类名和主题变量。
- [ ] 名词统一，和文档、确认框一致。
- [ ] 最常用的操作要几步？能不能少一步？出错提示说清了该怎么办？
- [ ] 320×568、390×844、横屏 740×360、桌面 1280×900 下：
  - [ ] 不滚动就能看到并点到主操作按钮（测试里不要先 `scrollIntoView`）；
  - [ ] 无横向溢出，弹出面板不出屏；
  - [ ] 按钮文字单行。
- [ ] 打开界面看一眼：插件名、标题、版本号都是对的。

## 测试

- [ ] 跑了全套自动测试（写明条数和结果）。
- [ ] 跑了浏览器检查（写明是模拟宿主）。
- [ ] 用上千条的大世界书或大名单试过。
- [ ] 真实酒馆里试过？真实手机（SillyDroid）上试过？没有就写“未实机验证”。

## 收尾

- [ ] 版本号已升（manifest.json 和 package.json 一致）。
- [ ] README、PLAN、NEXT、VERIFICATION 已同步；搜过旧说法。
- [ ] 没有提交过期的测试结果、临时文件或密钥。
- [ ] 清理了残留：调试输出、临时文件、截图、缓存、没用的分支。
- [ ] 清单、索引、校验和与实际文件一致（数量、文件名对得上）。
- [ ] 没有半成品：做不完的写清做到哪、剩什么，交接说明写进 NEXT 或问题记录。
- [ ] 推送后到远端核对最终状态：最新提交、CI 结果、文件确实在。
- [ ] 提交信息写了改了什么、为什么。
- [ ] 新踩的坑已记录：专门问题记在插件仓库的问题记录，通用问题交到 ai-dev-lessons `待审/`（插件仓库只留一行链接）。
- [ ] 这次是版本更新的话，已在 `CHANGELOG.md` 对应版本下写“更新人：家族名”。
- [ ] 按[交付汇报](../模板/交付汇报.md)发给用户，“未验证”和“同一问题第几次修”没有省略。
- [ ] 推送到 main，没有强制推送。
