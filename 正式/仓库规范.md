# 经验知识库规范（V2.0）

## 目的与责任

积累能改善未来模型判断、设计、创作、执行或验收的有效经验，让用户不必反复重述。经验萃取负责主动发现、还原、筛选、归类、按需检索和运用；仓库负责稳定的内容、范围、状态、索引和历史。未安装技能的 Agent 同样按本规范工作。

## 适用范围与效力

- 普适经验：在不同专业领域都成立；领域经验：特定专业内跨项目复用；专项经验：某类具体任务或产品内复用；项目专属：依赖特定项目、功能、版本或环境。选择证据和讨论支持的最窄充分范围；可用标签关联，不复制正文。来源场景不决定适用范围。
- 正式只表示已审核，不表示所有内容都应成为硬性命令。记录分别标注强制规范、指导原则、方法论、实践/避错经验、创新思想、技术知识等性质和适用条件。既有已审核开发规则保持原效力，软件开发规则不自动用于其他领域。只有适用的强制规范必须遵守；指导经验结合当前目标运用。当前明确用户指令及更高优先级规则优先，冲突应说明，不静默扩大授权。
- 正式/ 是共享规则和已审核经验的权威来源；项目文档补充项目约束。具体案例只作案例证据，技术参考按版本复核；待审/ 不是正式规则。

## 发现与准入

在实质性工作开始或阶段切换时主动继承经验；在有价值的思想形成、明确决定、重要纠正、实践完成等自然节点主动考虑沉淀。日常对话可能产生经验，但不要求每轮总结、每次提交或遍历所有历史。

以完整思想而非句子、轮次或字数为单位。先还原用户目标、原因、适用条件、实际效果，整合有价值的模型解释和后续确认。区分用户原意、模型澄清、模型新增判断、可核验事实及后续纠正；不把用户沉默当认可，不把未经验证的提议写成实测。

入库前检查四件事：未来 Agent 能用它做什么；脱离对话是否仍准确完整；范围与状态是否可靠；相比现有正式、待审、驳回条目是否有实质增量。常识只要能改善行为也有价值。废话、附和、纯情绪、重复、空泛口号、临时指令及无依据推断不入库。用户反馈与有依据的预防建议足以进入待审，不要求额外举证或先犯错。未成熟但有价值的思想先在获准的私有候选区或可见上下文保留；有重大歧义时集中确认。

## 归档、审核与权限

- 普适、领域及专项经验先在 [待审](../待审/README.md) 新增或建议加强原条目；明确写出建议范围、性质、用户意图与模型贡献、实际用途、确认状态与证据程度。清晰的用户反馈可在已获共享写入授权时直接交待审，无需逐条确认；此动作不代表用户已审核晋升。用户明确授权复核转正式，只能在该次范围内执行，写明审核授权、日期、去向及“审核通过”提交说明。
- 项目专属经验写入该项目已有的决策或问题记录，按项目授权操作；不能访问该项目时提供待写入文本，不改放共享正式区。不能确定通用性时先留项目记录标“可能通用”，不把专属细节双写到共享库。具体工具、平台、环境知识进入技术参考（需授权、公开安全且有复核说明）。
- 本仓库当前公开。读取/写入技术权限不等于允许公开用户内容；只有用户明确授权公开的非敏感经验可写入，即使是待审也一样。仅保存足够的匿名化解释与必要来源，不上传聊天全文、私有项目细节、个人敏感信息、密钥或凭据；未获公开授权、可能暴露信息或语义不清时留在可见上下文/获准私有位置。此规则不构成未来自动上传授权。
- 正式区修改（含规范、索引、正文、范围与效力）须有用户审核授权；合并、修正、失效均保留历史和原编号/映射。重复不新增，相关增量先建议合并，冲突不静默覆盖；驳回记录用于防止重复提交，不作为有效规则。历史技术参考不自动晋升。

## 检索与使用

1. 实质任务开始先读 README、此规范及[总索引](../总索引.md)；辨识领域、专项、项目、阶段与风险。软件开发读取[开发工作流程](工作流程.md)和[通用准则](通用准则.md)。其他领域只读相关入口。
2. 通过索引选读相关正式正文和适用强制要求，遇到阶段变化、新风险或复发再补查。无关领域、案例、所有模型文件及历史不整库读取。索引只定位，不替代适用正文；未读到的关键要求如实说明。既有规则引用旧路径或编号时，循兼容页进入对应正文。
3. 将命中的经验转化为本次具体行动和验收；开发开工报告写相关编号与行动，收尾说明执行/证据/未验证。不为报告凑条目，不能仅列编号当作已落实。
4. 经验库不可访问时继续能做的任务并说明未读取，不能编造命中；不强制为归档开展大规模调查或读取所有历史。遇到需要仓库外权限的工作单独确认。

## 维护与回滚

使用 Git 保留变更；不强推、不覆盖他人提交。正文与索引同次更新，维护稳定 ID 和兼容入口。正式规则审核流程见[待审区](../待审/README.md)；更新历史见[CHANGELOG](../CHANGELOG.md)，保留历史审核与[整理记录](../整理记录/)；更改工作方式不自动改变旧经验审核状态。远端写入后核对目标、提交、内容和 CI，区分本地、提交、推送、验证状态。
